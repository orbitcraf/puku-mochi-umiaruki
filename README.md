# ぷくともちの やまあるき

元気な「ぷく」と、のんびり屋の「もち」が山を登る、全11ページのデジタル絵本です。PCでは見開き、スマートフォンでは縦長の1ページとして表示され、ボタン・キーボード・スワイプでページをめくれます。

## 開き方

`index.html` をブラウザで直接開くだけで動作します。ローカルサーバーを使える環境では、このフォルダを任意の静的サーバーで配信しても動作します。外部通信・外部フォント・ビルドは不要です。

## GitHub Pagesで公開する

このプロジェクトは、GitHub Pagesのプロジェクトサイト（`https://ユーザー名.github.io/リポジトリ名/`）でも動くように、CSS・JavaScript・画像をすべて相対パスで参照しています。`main`ブランチへ更新を送ると、`.github/workflows/deploy-pages.yml`がサイト一式を自動公開します。ビルドやパッケージのインストールは不要です。

1. GitHubで空のPublicリポジトリを作成する（推奨名：`puku-mochi-yamaaruki`）。GitHub上ではREADME、`.gitignore`、ライセンスを追加しない。
2. このフォルダのローカルリポジトリを、そのGitHubリポジトリへプッシュする。
3. GitHubのリポジトリで `Settings` → `Pages` を開き、`Build and deployment` の `Source` を `GitHub Actions` にする。
4. `Actions` タブで `Deploy GitHub Pages` が緑のチェックになるまで待つ。
5. `Settings` → `Pages` の `Visit site` を押す。推奨名を使った場合のURLは `https://ユーザー名.github.io/puku-mochi-yamaaruki/`。

初回公開や更新の反映には数分かかることがあります。iPhoneでは公開URLをSafariで開いてください。音はブラウザの自動再生制限に合わせて初期OFFなので、ページ右上の「おと」をタップすると鳴ります。

### 公開設定の内容

- `.nojekyll`：Jekyll変換を行わず、静的ファイルをそのまま配信
- `.github/workflows/deploy-pages.yml`：`main`へのpush時と手動実行時に自動公開
- `scripts/check-static.mjs`：公開前にローカルURL依存、絶対ルートパス、参照切れを自動検査
- `index.html`：公開物のルートに置かれるエントリーファイル
- `assets/`：画像を相対パスで配信

### GitHub Pages公開前検証

- `/puku-mochi-yamaaruki/`配下に置いたローカル配信環境で、CSS・JavaScript・全画像の読み込みを確認
- `127.0.0.1`、`localhost`、`file:`、外部URL、絶対ルートパスへの依存がサイト本体にないことを確認
- 360px / 390px / 1024px / 1440pxで横スクロールが出ないことを確認
- 画像欠損とブラウザコンソールの警告・エラーがないことを確認
- 全11ページの前後移動、ハッシュURL、ブラウザ履歴、キャラクターのポーズ変更、場面反応、アルバムの開閉を確認

## あそび方

- ページ送り：画面下の「前へ」「次へ」、またはキーボードの左右キーを使用
- 最初／最後へ：キーボードのHome／Endを使用
- スマートフォン：絵本の上を左右にスワイプしてページ移動
- ページURL：`#page-forest`のようなURLを共有すると、そのページから開く
- キャラクター紹介：ぷく・もちをクリック、Enter、Spaceで表情とポーズを変更
- 場面の丸いボタン：草、鳥、川、風景などの小さな反応を表示
- 山の音：右上の「おと」でON/OFF。初期状態はOFF
- アルバム：最終ページの「おもいでを みる」から開き、Esc・背景・×ボタンで閉じる

## 現在の構成

- `index.html`：11ページの絵本、ページ送り、アルバムダイアログ
- `styles.css`：PC見開き、スマホ単ページ、ページめくり、キャラクターと場面演出
- `app.js`：ページ状態、ハッシュ履歴、キーボード・スワイプ、ポーズ、アルバム
- `sound.js`：ユーザーがONにした場合だけ鳴る場面別の環境音
- `game.js`：旧ミニゲームの復元用コード。現在の絵本からは読み込まない
- `assets/`：表紙、8場面、エンディング、キャラクター画像

Canvasミニゲームと「今日のやまあるき」は、絵本としての読みやすさを優先して現在のUIから外しています。`game.js`は将来再利用できるよう削除せず保持しています。

## 素材方針

添付画像は配色、絵本らしい質感、丸くふわふわしたキャラクター性、山の明るい空気感を読み取るための参照としてのみ使用しました。完成サイトには添付画像そのもの、ロゴ、コマ配置を流用せず、サイト用のオリジナル画像を生成して組み込んでいます。生成画像にはHTMLの文字や操作部品を焼き込まず、内容とUIを分離しています。

## 旧スクロール版：8回の改善記録

### 1. 世界観と色

- 問題：初期状態ではサイト固有のビジュアルがなく、添付画像の鮮やかな山の空気感を表現できなかった。
- 変更：シアン、青、緑、黄色、紫、ピンク、オレンジを主役にし、濃紺の太い輪郭と絵具の質感を持つオリジナル画像を作成した。
- 結果：黒背景や企業サイト風の印象を避け、最初の画面から同じ世界の新しい物語だと伝わる構成になった。

### 2. 第一画面の読みやすさ

- 問題：明るい風景だけではタイトルと操作の入口が景色に埋もれやすかった。
- 変更：左側に薄い青のグラデーションを重ね、濃紺で縁取った大きなタイトルと木製看板風ボタンを配置した。
- 結果：風景を隠しすぎず、タイトルと「ぼうけんを はじめる」が一目で見つかるようになった。

### 3. 山道の連続性

- 問題：各場面を単に縦に並べると、ひと続きの登山に感じにくかった。
- 変更：中央を蛇行する土色の道、進捗するぷく印、交互配置の8場面、スクロール時の拡大を追加した。
- 結果：ページを下る行為が山道を先へ進む感覚につながった。

### 4. 性格の違い

- 問題：説明文だけでは、ぷくともちの違いが体験として弱かった。
- 変更：ぷくは素早く跳ねて発見・食事へ切り替わり、もちは座る・眠る・景色を見る状態とゆっくりした台詞を持たせた。
- 結果：行動速度、姿勢、言葉のすべてで「行動派」と「マイペース」が対照的になった。

### 5. 動きと軽さ

- 問題：動きを増やしすぎると絵や文章が読みづらく、スマートフォンでも重くなる。
- 変更：雲、鳥、ヒーロー画像、ぷく、もちだけに緩やかな動きを限定し、画像をWeb用サイズへ縮小・圧縮した。`prefers-reduced-motion` にも対応した。
- 結果：にぎやかさを保ちながら視線が散りにくく、全画像一式も約4.5MBに収まった。

### 6. ミニゲームの操作感

- 問題：ページ内ゲームでは矢印キーとスクロールの競合、画面外落下、スマホ操作が課題になる。
- 変更：開始後だけキー入力をゲームへ渡し、論理解像度固定、落下時復帰、当たり判定、タッチボタン、再挑戦を実装した。
- 結果：PCでもスマートフォンでも、移動・ジャンプ・収集・山頂到達まで遊べるようになった。

### 7. 小さな遊びの操作性

- 問題：ランダム表示が同じ文を連続して出すこと、アルバム拡大後に操作位置を見失うことがあった。
- 変更：直前のメッセージを除外し、ネイティブダイアログ、Esc、背景クリック、閉じるボタン、元のカードへのフォーカス復帰を実装した。
- 結果：短い操作でも毎回変化があり、キーボードでも迷わず元の場所へ戻れる。

### 8. スマートフォンと最終統一

- 問題：狭い画面では中央の山道、ゲームHUD、アルバムの不揃い配置が横にはみ出しやすかった。
- 変更：820pxと520pxでレイアウトを切り替え、物語を片側1列、ゲームHUDを2段、アルバムを1列にした。タップ領域は44px以上を確保した。
- 結果：360px、390px、1024px、1440pxの各幅で、横スクロールを出さずに最後まで読んで遊べる構成になった。

## 確認項目

- キーボードとタッチの両操作
- 画像の遅延読み込み
- モーション軽減設定
- フォーカス表示、代替テキスト、44px以上の主要操作領域

## 追加仕上げ：5回の改善記録

### 1. ふたりの動きの差

- 問題：カードを押した時以外は、ぷくともちが同じように静止して見えた。
- 変更：ぷくには短い間隔の跳ねる待機動作と即時反応、もちにはゆっくりした呼吸、座る・眠る動作と反応の間を追加した。
- 結果：操作前から「先へ行きたいぷく」と「その場でくつろぐもち」の違いが見えるようになった。

### 2. スクロール物語の連続性

- 問題：場面画像は並んでいたが、背景とふたりの状態が場面間でつながっていなかった。
- 変更：登山口、森、川、急坂、休憩、山頂、夕焼けの7場面に整理し、中央の山道を歩く小さなふたりと背景色を現在の場面に合わせて切り替えた。
- 結果：スクロールすると、ぷくが先行し、もちが少し遅れ、休憩では眠り、最後は夕方になる一続きの登山になった。

### 3. セリフの短さと反応

- 問題：以前のセリフには説明的で長いものがあり、クリックの反応もカード下部だけで分かりにくかった。
- 変更：「いくぞー！」「みつけた！」「ちょっと やすむ…」「まだ のぼるの？」などへ短縮し、顔の近くに一時的な吹き出しを表示した。
- 結果：絵本の一コマのように、表情とひとことを同時に読めるようになった。

### 4. ふたりで進むゲーム

- 問題：ぷくだけを動かして山頂へ行く内容では、性格差がゲームのルールになっていなかった。
- 変更：もちが遅れて追いかけ、途中で座って休み、距離が開くとぷくが待つ仕組みを追加した。距離メーターと、おにぎりで少し元気になる動作も追加した。
- 結果：速く進むだけではなく、もちの歩幅を見ながら一緒にゴールするゲームになった。

### 5. 背景反応・音・スマホ最終調整

- 問題：風景を見る以外の反応が少なく、スマホではゲーム見出し、開始ボタン、おにぎり表示が不自然に折り返す箇所があった。
- 変更：鳥、草、川、小石、風、山びこ、夕空に触れる小さな反応を追加した。鳥・川・足音・風はWeb Audioで控えめに生成し、初期OFFの切り替えボタンを設置。390px表示で文字の折り返しも調整した。
- 結果：風景にそっと触れられ、必要な時だけ音を楽しめるようになった。360px／390pxでもゲーム操作と表示が収まることを確認した。
